# 个人工作台 · 全文搜索功能设计

> 状态：**P0 与 P1 已实现并通过全部验证（2026-09-12）**，实施记录见 §13
> 范围：跨 收录 / 任务 / 日程 / 备忘 / 时间线 五类实体 + 回收站
> 相关文档：`产品设计说明.md`（统一语言、视觉规范）、`开发文档-Java8版.md`（接口契约风格）

---

## 1. 一句话定义

**顶栏常驻搜索框，输入即搜，左侧结果列表 + 右侧预览，覆盖五类实体与回收站，支持语义联想，回车直接定位到那一条。**

它不是一个"搜索页签"，而是随时可用的一个"层"：在任何页签下都能唤起，结果不打断当前上下文。

## 2. 已确认的产品决策

| # | 决策点 | 结论 | 备注 |
|---|---|---|---|
| D1 | 入口形态 | **顶栏常驻输入框** | 可见性最高；窄屏降级为放大镜图标 |
| D2 | 打开方式 | **浮层内先预览再跳** | 左侧列表 + 右侧预览的分栏结构 |
| D3 | 检索范围 | **全部，含回收站** | 需配套"状态标记 + 活数据优先 + 独立分组"三条补偿规则 |
| D4 | 检索能力 | **关键字 + 语义联想** | 两段式渲染，LLM 失败静默退化为纯关键字 |

以下三条由设计侧固定，不再作为选项：

| # | 规则 | 理由 |
|---|---|---|
| F1 | 排序**不跨类型混排**，按 任务 → 日程 → 备忘 → 收录 → 时间线 → 回收站 固定分组 | 跨类型混排会带来"为什么这条排前面"的困惑，收益极小 |
| F2 | 回收站数据**单独成组、沉到最后**，行内灰化并标"在回收站 · N 天前删除" | 与活数据混排会让用户以为对应页面坏了（页面上确实看不到） |
| F3 | **不引入 SQLite FTS5** | 单机单用户、数据千级；FTS5 需付出迁移 + 中文分词器（`unicode61` 对中文无效）+ 索引同步三重代价，收益接近零 |

## 3. 交互规格

### 3.1 入口

| 方式 | 行为 |
|---|---|
| 点击顶栏搜索框 | 展开搜索面板，光标入框 |
| `Ctrl / ⌘ + K` | 任意页签下聚焦搜索框并展开面板（零成本的补充入口，与常驻框共存） |
| 窄屏（≤768px） | 搜索框收为放大镜图标，点击展开同一面板（此时面板占满宽度） |
| `Esc` | 有内容时先清空输入；输入为空时收起面板 |
| 点击面板外部 / 切页签 | 收起面板，**保留查询词** |

### 3.2 面板结构（自上而下）

1. **输入行**：放大镜 + 输入框 + `Esc 关闭`（窄屏无此项）
2. **汇总行**：`N 条结果 · 用时 Xms` + 语义补位提示 chip + `全部 / 仅活数据` 切换
3. **类型 chips**：`任务 2` `备忘 3` `日程 1` `收录 1` `时间线 1` `回收站 1`，点击过滤（多选，默认全选）
4. **分栏主体**：
   - 左侧结果列表（272px 固定）：分组头 + 结果行
   - 右侧预览（占满剩余）：实体标记 + 标题 + 匹配来源 + 正文 + 键值信息 + 操作按钮
   - 窄屏：收起预览，仅保留列表，结果行内展示更长片段
5. **底部键盘条**：`↑↓ 选择结果` `Tab 收起预览` `Enter 打开并定位`；右侧固定提示"回收站结果将跳到回收站页"

### 3.3 结果行

```
[图标] 标题（命中词高亮）
       元信息 · 匹配来源
```

- 图标：沿用项目既有的单字方块风格（`任` `程` `忘` `收` `线`），按实体类型着色
- 元信息：任务 `P1 · 进行中 · 9-13`；日程 `会议 · 周四 14:00`；备忘 `工作 · 3 天前`；收录 `待整理 · 今天 09:12`；时间线 `完成 · 今天 10:05`
- 匹配来源：`精确命中`（默认色）或 `联想：限速 → 限流`（琥珀色）
- 回收站行：整体灰化，元信息为 `在回收站 · 8 天前删除`

### 3.4 键盘路径

| 键 | 行为 |
|---|---|
| `↑` `↓` | 在当前可见列表中移动选中项，**跨分组连续**（不分组内循环），到底/到顶不回绕 |
| `Enter` | 打开选中项并定位（见 §5） |
| `Tab` | 收起 / 展开右侧预览（展开时焦点仍在输入框，不需要二次 Tab） |
| `1`–`6` | 快速切换类型 chip（可选，P1） |

> 选中项跨分组移动时必须**把该行滚进视野**，且左侧列表独立滚动，不带动整页。

### 3.5 空态

| 状态 | 展示 |
|---|---|
| 未输入 | `最近搜索`（最近 5 条，可点击回填）+ 高频目标快捷入口（现在的任务 / 今天的日程 / 待整理）。**不留空白面板** |
| 有输入、无结果 | `没有找到「XXX」` + 主按钮 `把「XXX」收录到收集箱`（复用 `POST /api/v1/inbox`）+ 次按钮 `清除筛选条件`（当类型 chips 过滤导致空结果时，后者才是主按钮） |
| 加载中 | 输入行右侧显示细进度条；**不遮挡已有结果**（保留上一次结果直到新结果返回，避免闪烁） |
| 网络失败 | 面板内一行 `暂时无法连接工作台` + `重试` 按钮，**不弹 toast**（toast 会盖住输入框，用户正需要重试） |

## 4. 结果 → 定位映射表

**这是本功能最容易做错的部分**，逐条对照实现。

| 实体 | 目标页签 | 定位动作 | 注意 |
|---|---|---|---|
| 任务 | `tasks` | **先清筛选**（`state.taskFilter="all"`、隐藏 `.filter-note`）→ `renderTasks()` → 滚动并高亮该行 | 不清筛选会让高亮的元素根本不在 DOM 里 |
| 日程（有日期） | `schedule` | **先把该日期所在那一周放进可见列表**（`ensureWeek(weekStartOf(date))` → `await loadEvents()` → `scrollToWeek()`）再高亮 | 顺序不能反：周条不进 DOM，高亮的选择器就找不到它。日程页自 2026-09-13 起是周视图，见 `docs/日程周视图设计.md` |
| 日程（时间待定） | `schedule` | 切页签后滚到「待定时间」区并高亮 | `event_date IS NULL` 是合法状态，**任何方向都不补今天** |
| 备忘 | `memos` | **先切到所属空间**（`setMemoGrp(work/life)`）→ 高亮；若该备忘已归档，需同时打开"显示已归档" | 空间不对 → 高亮目标不在 DOM 里 |
| 收录 | `inbox` | 切页签后高亮。**需同时能定位 `pending` / `failed` / `processing` 三种子列表** | `failed` 条目只在「待整理」区露出 |
| 时间线 | `timeline` | 切页签后**展开那一天**（`state.timelineCollapsed[day]=false`）再高亮 | 折叠状态下高亮目标不可见 |
| **回收站（任何实体）** | `trash` | 切回收站页并高亮该行 | **不能跳原实体页**：那些页面查 `deleted=0`，软删数据在那里不存在，跳过去等于"点了没反应" |

**统一实现方式**：后端在每条结果里返回 `target.tab` 与必要参数（如 `date`、`grp`），前端由**一个** `openSearchResult(item)` 函数 switch 分发。禁止在渲染结果行时各自内联跳转逻辑。

高亮统一复用现有 `highlightRow(element)`：加类 → `scrollIntoView({block:"center"})` → 1.6s 后移除类。

## 5. 检索与排序规则

### 5.1 检索字段

| 实体 | 检索字段 |
|---|---|
| 任务 | `title`、`note`、`description` |
| 日程 | `title` |
| 备忘 | `title`、`content`、`tags`、`url` |
| 收录 | `raw_content` |
| 时间线 | `content` |
| 回收站 | 上述对应实体的字段，条件为 `deleted = 1` |

### 5.2 中文检索策略

复用 `AssistantService` 已有的 **CJK 二元组分词**（`terms(q)`）思路：

1. 查询词去空白、转小写
2. 连续 CJK 字符切成二元组（`限流` → `限流`；`速率限制` → `速率`/`率限`/`限制`）
3. 英文/数字按空白与标点切词，保留整体
4. SQL 侧：`(LOWER(字段) LIKE ? ESCAPE '\' OR ...)` **逐个词 AND**（每个词都要在任一字段出现）
5. 复用现有 `escapeLike()` 处理 `%` `_` `\`

> 不要对中文用 `LOWER()` 期待效果——它对中文无效但无害，保留是为了英文大小写不敏感。

### 5.3 打分与排序

**组内**按下表累加，降序排列；**组间**顺序固定（§F1），不参与全局排序。

| 加分项 | 分值 |
|---|---|
| 标题 / 整体词命中 | +100 |
| 标题分词命中 | +60 |
| 标签命中 | +40 |
| 正文 / 备注 / 描述命中 | +25 |
| 收录原文命中 | +20 |
| 时间线内容命中 | +15 |
| **语义扩展词命中** | 对应分值 × 0.5 |
| 7 天内更新 | +8 |
| 已删除 | −30（只降排序，**不隐藏**） |
| 已归档备忘 / 已取消任务 | −10 |

同分并列时按 `updated_at` 降序，再按 `id` 降序，**保证结果稳定**（同一查询两次执行顺序必须一致，否则测试无法断言）。

### 5.4 截断必须说出来

单分组默认返回 5 条，全局上限 20 条。

- 某分组被截断 → 该分组底部显示 `该分组还有 N 条未显示`，点击后展开该分组
- 全局被截断 → 汇总行显示 `仅显示前 20 条`
- **禁止静默截断**（这是本项目已发生过的事故类型）

## 6. 接口契约

### 6.1 检索

```
GET /api/v1/search?q={关键词}&types={task,memo,...}&scope={all|active}&limit=5
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `q` | 是 | 1–100 字；为空或超长返回 `1002` + 中文原因 |
| `types` | 否 | 逗号分隔，缺省=全部六类；非法值返回 `1002` + 列出合法值 |
| `scope` | 否 | `all`（默认，含回收站）/ `active`（仅活数据） |
| `limit` | 否 | 单分组条数，默认 5，上限 20 |

响应：

```json
{
  "code": 0,
  "data": {
    "query": "限速",
    "expandedTerms": ["限流", "速率限制"],
    "semanticState": "ready",
    "elapsedMs": 18,
    "truncated": false,
    "totalCount": 12,
    "groups": [
      {
        "type": "task",
        "label": "任务",
        "total": 2,
        "hasMore": false,
        "items": [
          {
            "id": 12,
            "entity": "task",
            "title": "QPS 与日配额的两级限流策略",
            "snippet": "单机 QPS 上限 200，单通道日配额 5 万…",
            "matchedTerms": ["限流"],
            "matchKind": "exact",
            "matchField": "title",
            "deleted": false,
            "meta": { "priority": "P1", "status": "doing", "due": "2026-09-13" },
            "updatedAt": "2026-09-11T18:20:00",
            "target": { "tab": "tasks" }
          }
        ]
      }
    ]
  }
}
```

关键字段语义：

- `semanticState`：`off`（未启用）/ `pending`（扩展词计算中，前端保持轮询或等待）/ `ready` / `failed`
- `matchKind`：`exact` | `semi`（分词命中）| `semantic`（联想命中）
- `target.tab`：**定位动作的唯一依据**；日程结果额外带 `target.date`（可为 `null` 表示待定），备忘结果带 `target.grp`

### 6.2 语义扩展（独立接口，便于两段式渲染）

```
POST /api/v1/search/expand  { "q": "限速" }
```

响应 `{ "terms": ["限流", "速率限制"], "cached": false }`

- 服务端缓存：同一 `q` 命中缓存直接返回，TTL 24 小时
- LLM 调用超时 **1200ms**，超时/失败返回空数组且 `code` 仍为 `0`（**语义是增强不是依赖，不允许因此报错**）
- 未配置 AI 或未启用时直接返回空数组，前端不显示语义相关 UI

### 6.3 错误处理

- 所有客户端错误走 `1002` 并附中文可操作原因（如"关键词超过 100 字，请缩短后重试"）
- 请求 DTO 的校验注解必须带中文 `message`（由 `ValidationMessageTest` 守住）
- **不新增兜底映射**：注意不要用宽泛的 `@RequestMapping` 兜底把 405 吃成 404

## 7. 前端改造点

| 文件 | 改动 |
|---|---|
| `index.html` | 顶栏增加 `#globalSearchInput`；`<header>` 之后增加 `#searchPanel` 结构（**放在所有 `.view` 之外**，因为要覆盖在任意页签之上）；窄屏增加放大镜按钮 |
| `api.js` | 新增 `search(params)`、`expandSearch(q)` |
| `app.js` | 新增 `openSearchPanel()`、`closeSearchPanel()`、`runSearch()`、`renderSearchPanel()`、`moveSearchSelection(delta)`、`openSearchResult(item)`、`renderSearchPreview(item)`；**高风险改动见下** |
| `style.css` | 新增 `.gs-*` 前缀类（`gs-panel` / `gs-list` / `gs-row` / `gs-preview` / `gs-mark`），避免与现有类冲突 |

### 7.1 三条红线

1. **搜索不得调用 `refreshAll()`**
   现状：`#memoSearch` 的 `input` 事件直接调 `refreshAll()`，**每敲一个字符打 11 个接口并全量重绘 11 个视图**。搜索走独立 `state.search`，不参与 `refreshAll` 的 11 路拉取。顺手把备忘搜索改成防抖 + 只重渲染备忘列表。
2. **高亮必须先转义再包标签**
   正确：`esc(title).replace(esc(term), "<mark class=\"gs-mark\">"+esc(term)+"</mark>")`
   错误：把用户输入拼进 `innerHTML`。本项目 `esc()` 已覆盖引号，但**逐词高亮时容易漏转义**，必须写成工具函数 `highlight(text, terms)` 统一处理。
3. **搜索状态不放进 `state` 顶层被 `refreshAll` 覆盖**
   用 `state.search = { q, groups, flatItems, activeIndex, scope, typeFilter, semanticState, requestSeq }`；`refreshAll()` 重建 `state` 时不得重置该对象。

### 7.2 请求并发控制

- 输入防抖 **200ms**
- 每次请求自增 `requestSeq`，响应回来时若 `seq !== state.search.requestSeq` 则**丢弃**（防乱序覆盖）
- 用 `AbortController` 取消上一条未完成请求（`api.js` 的 `request()` 需支持传入 `signal`）
- 语义扩展请求独立发起，**不阻塞**关键字结果渲染

## 8. 数据库变更

**本功能不需要 DDL 变更**，也不需要新增索引（数据量千级，现有索引足够）。

可选（P1「最近搜索」用）：

```sql
-- V8__search_history.sql
CREATE TABLE search_history (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    keyword       TEXT NOT NULL,
    hit_count     INTEGER NOT NULL DEFAULT 0,
    last_used_at  TEXT NOT NULL,
    CONSTRAINT uq_search_keyword UNIQUE (keyword)
);
```

语义扩展词缓存可复用 `app_config`（key 前缀 `search.expand.`），也可另建表，二者都不影响主链路。

## 9. 语义匹配方案

### 9.1 一期：查询扩展（Query Expansion）

```
用户输入「限速」
  ├─ 立即：关键字检索（含 bigram 分词）→ 渲染结果（<50ms）
  └─ 并行：POST /search/expand → 得到 ["限流","速率限制"]
            └─ 用扩展词再跑一次检索，去重合并 → 追加"联想命中"结果
```

界面上必须能让用户看到"结果在补位"：汇总行 chip `含 2 条与「限速」语义相近` 在补位时先显示 `正在联想相近说法…`，补到后变为结果数。

Prompt 要点（约束输出稳定）：要求返回 JSON 数组、3–5 个词、只输出同义/近义/常见缩写、不输出解释、不含原词。

### 9.2 二期（可选）：向量检索

数据量到万级、或查询扩展仍不够时再考虑：embedding + SQLite 存 BLOB + 应用层余弦相似度。
**不建议现在做**：需要额外 embedding 依赖、索引重建、以及"为什么这条相似"的解释成本。

### 9.3 明确不做

- ✗ 拼写纠错（中文场景收益低）
- ✗ 跨 Vault 笔记全文（那是「知识库问答」的职责，两者不要重叠）
- ✗ 搜索结果内的二次检索（复杂度高，用类型 chips 替代）

## 11. 验收清单（可执行）

### 11.1 功能

1. 任意页签下点击顶栏搜索框，面板展开，输入框获得焦点
2. 输入"限流"，五个分组均有结果，高亮词出现在标题或片段中
3. `↑↓` 跨分组连续移动，选中行始终在视野内
4. `Enter` 打开任务结果 → 切到任务页、目标行高亮、`scrollIntoView` 居中
5. 打开**日程**结果 → 日程页把它所在的**那一周**放进可见列表（并滚动过去），目标卡片高亮
6. 打开**时间待定**的日程结果 → 停在待定区，**日期未被改成今天**（查 DB 断言 `event_date IS NULL` 未被写入）
7. 打开**备忘**结果（生活空间）→ 备忘页切到「生活」空间后目标行高亮
8. 打开**回收站**结果 → 跳到回收站页并高亮（**断言未跳到任务/日程/备忘页**）
9. 切换 `仅活数据` → 回收站分组消失、`totalCount` 减少、回收站行不再出现
10. 类型 chip 取消「任务」→ 任务分组消失；全部取消 → 显示清除筛选空态
11. 无结果时点 `把「XXX」收录到收集箱` → `POST /inbox` 成功，收录页出现该条
12. 语义补位：输入"限速"能搜到标题含「限流」的条目，且该行标 `联想：限速 → 限流`

### 11.2 正确性（重点）

13. **`refreshAll` 不被触发**：打开搜索面板并输入，网络面板中**只有 `/api/v1/search` 与 `/search/expand`**，无 `dashboard`/`tasks`/`memos`/`activity` 等 11 个接口
14. **请求乱序不覆盖**：输入"限流"后立刻改成"限速"，最终结果对应"限速"（可用人工延迟接口验证）
15. **高亮不产生 XSS**：搜索 `<img src=x onerror=alert(1)>`，页面不执行脚本、不出现破图，文本原样显示
16. **引号不破坏渲染**：搜索 `复盘"双十一"`，结果行结构完整（属性上下文未被撕开）
17. **`%` 与 `_` 不被当通配符**：搜索 `100%`，不返回全部记录（`escapeLike` 生效）
18. **中文不乱码**：断言中文响应体时 `getContentAsString()` 必须显式传 `StandardCharsets.UTF_8`
19. **截断可视**：造 8 条含同一关键词的任务，分组底部出现 `该分组还有 3 条未显示`
20. **软删数据不进活数据组**：软删一条任务后搜索，该条只出现在回收站分组

### 11.3 视觉与响应式

21. 面板展开时**不遮挡**顶栏其他元素，且页面不产生横向滚动条
22. 961px 视口下面板分栏正常；768px 以下收起预览、搜索框变图标

### 11.4 限制与说明（不通过即视为 bug）

## 12. 容易跑偏的地方

1. **跳转顺序反了**：日程 `setViewDate` 必须在切页签/渲染之前；任务筛选必须在下钻前清空。顺序错 → 高亮目标不在 DOM → 表现为"点了没反应"。
2. **回收站结果跳原实体页**：最常见的错误实现，因为它"看起来对"。
3. **大按钮尺寸牵动布局**：新增顶栏元素后必须扫一遍宽度，961px 是最窄可分栏档位，960px 已塌成单列。
4. **`maxlength` 与后端 `@Size` 必须一致**（搜索词 100 字），且检查脚本应读 Java DTO 断言，不写死数字。
5. **高亮工具函数被绕过**：只要有一处直接拼 `innerHTML` 就是 XSS 缺口，必须集中到 `highlight()` 一个函数。
6. **把搜索做成 `refreshAll` 的触发器**：这是现存 `#memoSearch` 的问题，别复制它。

### 13.2 与设计的差异（都是实现中发现设计不够具体的地方）

| # | 设计原文 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | 类型 chips 通过 `types` 参数过滤 | **前端本地过滤** | 结果本来就是全量下发的（每组已被后端 limit 截断），本地过滤不会漏条目，而且 chips 上的数量始终完整、切换零延迟。后端 `types` 参数保留可用 |
| 2 | 扩展词由前端逐词再搜一遍 | **搜索接口加 `expand` 参数** | 扩展词之间是 OR 关系，逐个请求会把同一条结果拆成好几份，去重和排序都做不了 |
| 3 | 未明确「搜索不做的事」 | 搜索**不写 `activity_log`**、**不修改任何数据** | 搜一下不是业务动作，写进时间线会把真正的流水淹掉 |

### 13.3 实现中发现并修复的三个缺陷（都是真页面冒烟才暴露的）

1. **回收站命中跳回收站页** —— 设计里已写明，实现时用断言钉住了。这条属于"设计对了、靠验证守住"。
2. **输入新词后立刻按 Enter 会打开上一次的结果**（数据竞态）
   - 现象：用户敲完一个词马上回车，列表里还是上一次的结果，于是跳到一条他根本没在看的记录上；界面看起来完全正常。
   - 修复：加 `search.resultQuery`，回车时比对输入框与"这批结果对应的关键词"，不一致就不打开并提示。
3. **点类型 chip 会把面板关掉**（DOM 竞态）
   - 现象：点一下筛选，刚打开的面板自己关了，控制台一个字都不报。
   - 根因：chip 的处理器会**同步重绘**整个 chips 容器（`innerHTML` 整体替换），事件继续冒泡到 `document` 时 `event.target` 已脱离文档树，`closest("#searchPanel")` 返回 `null`，被判成"点了面板外面"。
   - 修复：改用 `event.composedPath()` 判断事件路径（它在事件派发时就定好了，不受后续 DOM 变动影响）。
   - **通用教训**：任何"点击处理会重绘自身容器"的按钮，都不能用 `closest(target)` 判断点击区域。
4. **`Tab` 只能单向收起预览** —— 原实现给"键盘用户留出口"留成了一个单向开关，第二次按 Tab 不会展开。改成双向，出口交给 `Esc`。

### 13.6 真实数据抽查（不构造夹具，直接读真实库）

前面几层验证用的都是自己造的数据，回答不了「拿真实的中文数据去搜，结果合不合理」。
`output/ui-preview-search/recall_probe.py`（**只读**打开 `dev-data/workbench.db`，
严格复刻 `SearchTerms.split` 与 `SearchService` 的检索条件）在真实数据上抽查：

| 项 | 实测 |
|---|---|
| 库规模 | 任务 12 / 日程 9 / 备忘 6 / 收录 18 / 时间线 79 |
| 常用词召回 | 「王佳纯」→ 任务 1 + 时间线 7；「方案」→ 备忘 1 + 时间线 3；「测试」→ 任务 1 + 时间线 4 |
| 单字词 | 「删」→ 时间线 4（单字退化为整串匹配，没有出现"搜不到"） |
| 耗时 | 全部 **0.2–1.0ms** |

三条结论：

1. **「不引入 FTS5」的判断得到验证**：数据量百级、查询毫秒级，FTS5 的三重代价换不来任何东西。
2. **二元组的召回是合理的**，没有出现"搜一个词出来一大片无关记录"——因为词之间是 AND，
   多一个词只会更窄。搜「和王佳纯沟通」会被切成 `和王/王佳/佳纯/纯沟/沟通` 五个词并**全部要求命中**，
   所以只有那句话真正连续出现过的记录才会被召回。
3. **收录类的范围设置得到真实验证**：搜「今天下午四点」时，内容完全相同的**已归档**收录条目
   没有出现在结果里，只命中了由它生成的日程 —— 正是「收录 = 待整理 / 待确认」这条约定该有的表现。
