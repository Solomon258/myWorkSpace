日程新增表单 · 视觉与对齐方案

这是纯设计稿，尚未改动任何产品代码。左侧「现状」面板用的是 style.css 里 原样抄来的 composer / c-row / tp 规则，所以问题是真的；右边三套候选全部复用项目既有 token，可直接落地。

日期默认填今天；清空日期则生成待定日程，它会落到下面的「待定时间」区。

实测（下方 shot-log 同源）：五个控件宽度 83/94/94/144/135px，合计 550px，容器 1018px → 右侧空 436px；控件的顶边跨度 13px、底边跨度 12px —— 图上 ①②③ 打点处即对应下面这几条：

1
没有字段标签：类型 / 开始 / 结束 / 日期 / 重复 全靠位置猜。两个 type=time 长得一模一样，看不出哪个是开始、哪个是结束。这是「看不清」的第一来源，也最容易填错。
2
高度不齐：.tp 是 inline-grid，里面是「时间框 + 一排 chips」两行，实测高 63px，旁边的 select / date 只有 38px。父级 align-items:center 让同行控件垂直居中，于是时间组上下各凸出一截 —— 实测这一行控件的顶边跨度 13px、底边跨度 12px。
3
宽度各行其是：.c-row 是 flex-wrap + 全部 width:auto。实测五档宽度依次是 83 / 94 / 94 / 144 / 135px（「会议」83px、「不重复」135px）—— 按内容宽度贴左排完只占 550px，右侧空出 436px，整行进不了栅格。
4
折行点随机：因为是 flex-wrap，窗口一窄就在任意位置断开，可能断在「开始 / 结束」中间，把一段时间拆到两行。布局不可预测。
5
主按钮被淹没：「加入」和 ＋AI / 附件 / 识别填表 / 问号 挤在同一行，字号、高度全一样（34px），视觉上没有主次，回车之外的点击路径很难一眼找到。
6
编辑弹层同样的问题：.mm-row.mm-even 是「两列等宽」，「类型」只有三个短选项却占掉半行；「开始 / 结束」那行又因为 .tp 比「类型 / 日期」行高，两行不等高。

类型换成三段控件：三选一用按钮组替代下拉，少一次点击、选项常显，并且用日程卡片的类型色（绿 / 蓝 / 灰）做小方块，跟周视图里的卡片颜色对上。

主按钮有了位置：「加入日程」独立成底栏右侧的主按钮（.btn.primary），左侧放次要动作。回车提交与点击提交都保留。

代价：实测展开区 340px，比现状（216px）高 124px —— 多了一行标签 + 一行底栏。换来的是「一眼看清 + 不会填错」。窄屏（≤640px）栅格自动塌回单列。

建议的落地顺序：先上 A（纯 CSS + 加标签，风险最小、能立刻消掉「不齐」和「看不出哪个是开始」两个最大痛点）； 如果你更在意信息可分步阅读、以后还要加「地点 / 参会人」，选 B； 如果你觉得展开态太高、且屏幕常年 ≥1280px，选 C。 三套可以混用 —— 比如 A 的栅格 + C 的内联时间条，就是「既齐又矮」的组合（本页 C 面板实际已经是这个组合的形态）。

另外两处顺带的小改动，无论选哪套都建议一起做：①「加入」独立成底栏主按钮；②类型用日程卡片的类型色（绿 / 蓝 / 灰），和周视图里卡片颜色对上，扫一眼就知道这条会显示成什么颜色。
